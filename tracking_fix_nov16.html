3. Why the copies happen (confirmed from the zap steps)

The RevPilot zaps run in the same Zapier account that Grok Bot can reach, so I read each zap's steps directly. To do that, I made disabled copies, read them, and deleted them. The live zaps were never touched.

  1. 05 Installation Complete (380215362) looks for an opportunity that is active and already in Job Complete. Job Complete is a "won" stage, so that search can never match. It creates a new empty opportunity every time and moves it to Job Complete. This is where the blank Job Complete sales come from (Aaron 11/14, Alejandro 11/13).
  2. 06 Installation Not Complete (380215694) looks for an active opportunity already in Job Not Complete Follow Up. If it doesn't find one, it creates an empty one.
  3. 04 Agreement Status (380198229) works the same way. The "Agreement Sent" path looks only for a deal in Contract Sent, and the "Agreement Signed" path looks only for one in Contract Signed. Either path creates a new deal when it doesn't find a match. The Signed path sends a blank value, which explains the $0 Contract Signed deals.
  4. 03 Not Sold (380198664) never creates a deal. It moves the active deal to Deal Lost, which is a "lost" stage. Its Follow Up path sets the lead status to Qualified, the same status the Sold zap sets. I can't see what created Alex Dena's Contract Sent deal on 10/16.
  5. 02 Sold (380197575) only sets the lead to Qualified and the owner. 02 Sold PandaDoc (380234494) sends the PandaDoc agreement and logs "Agreement Sent". It skips that if an Agreement Sent activity was already logged today, so re-saving a Sold card on a later day sends the agreement again. Neither one creates an opportunity. The Sold card opportunity must come from n8n "biscayne-close-to-hcp", which I can't see. That would also be where Aaron's $1,200 RO card failed.
